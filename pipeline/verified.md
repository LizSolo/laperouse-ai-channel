# Проверка фактов за 2026-08-31

## Пост 1. Claude удалил 700 ГБ данных разработчика

Первоисточник: https://habr.com/ru/news/1076130/ (открыт целиком, WebFetch)
Подтверждение: https://vc.ru/ai/3102692-claude-udalil-dannye-razrabotchika-iz-za-oshibki-v-skripte-ochistki (открыт целиком, WebFetch)
Путь применён: F-01 путь 1 — первоисточник открыт целиком, второй источник открыт и подтверждает
дословно.

Факты:
- Разработчика зовут Себастьян Гийемо (в англоязычных источниках — Sebastian Gllmt/Guillemot).
- Он попросил Claude написать скрипт, который помещает временные файлы каждого ИИ-агента в
  отдельную папку внутри /tmp и автоматически очищает её после завершения работы агента.
- Скрипт писала модель Claude Fable 5.
- Скрипт выполняла модель Claude Opus 4.8 — после того как система безопасности Anthropic
  переключила сессию с Fable 5 на Opus 4.8 (habr и vc.ru согласны в этом факте).
- Ошибка: в коде одно и то же имя переменной использовалось и для пути, который проверяла
  защита от случайного удаления, и для пути, который скрипт должен был удалить. В результате
  под удаление попал не /tmp, а домашний каталог разработчика.
- Удалено 700 ГБ данных.
- Полной резервной копии у разработчика не было.
- Часть данных восстановлена через git и логи сессий агентов; полностью восстановить не
  удалось.
- Сама папка /tmp, ради очистки которой писался скрипт, осталась нетронутой.
- Дата публикации новости: 28-29 августа 2026 (habr — 29.08, vc.ru — 28.08; давность на
  момент прогона 31.08 — 2-3 дня, T-07 не применяется).

Названия в тексте: Claude, Claude Fable 5, Claude Opus 4.8, Anthropic — все присутствуют выше.

## Пост 2. Три стадии внедрения ИИ в малом бизнесе (Inc.com)

Первоисточник: https://www.inc.com/reed-wilson/why-ai-feels-so-hard-for-small-businesses/91392567
(WebFetch на inc.com заблокирован окружением — EGRESS_BLOCKED)
Подтверждение: факты собраны перекрёстно по трём независимым запросам WebSearch (31.08),
каждый раз выдававшим дословные цитаты из этой же статьи; независимое использование того же
трёхстадийного деления не найдено на других доменах, поэтому в посте используются только
формулировки, дословно повторившиеся минимум дважды в разных запросах.
Путь применён: F-01 путь 2 — первоисточник закрыт для автоматических запросов (домен вне
allowlist), факты собраны перекрёстным поиском, как предписывает `prompts/author.md`, ШАГ 3.

Факты:
- Автор — Reed Wilson, CEO компании Courser.
- Статья на Inc.com «Why AI Feels So Hard for Small Businesses», дата публикации 20 августа
  2026 (давность на момент прогона 31.08 — 11 дней, в пределах 30 дней по T-11; больше 72
  часов, поэтому по T-07 давность нужно назвать в первых предложениях поста).
- Вывод сделан на основе работы автора с бизнесами в партнёрской сети Courser.
- Стадия 1: «ИИ уже есть в вашем бизнесе, вы просто не знаете где» — сотрудники используют
  ChatGPT, Copilot и подобные инструменты для писем, резюме встреч, анализа таблиц, без
  согласования и часто без понимания риска.
- Стадия 2: «Вы купили инструменты. Теперь дайте им задачу» — компании не выбрали конкретную
  бизнес-задачу, сотрудники пробуют разные промпты наугад. Совет автора: перестать
  воспринимать ИИ как волшебную палочку и начать с разбора повторяющихся задач команды.
- Стадия 3: «Измеряйте бизнес-результат, а не активность в ИИ» — вопрос «помогает ли это
  бизнесу» важнее количества сотрудников, которые пользуются ИИ каждый день.
- Главная ошибка, по автору, — пытаться перепрыгнуть через стадию, не решив то, что стоит
  перед компанией прямо сейчас.

Названия в тексте: Inc.com можно не называть по бренду (упоминание "Reed Wilson" и "Courser"
допустимо как обобщение практика без раскрутки конкретного продукта); если в посте
упоминается Courser — название присутствует выше.
