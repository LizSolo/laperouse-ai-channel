## Пост 2

```
Если код для вас теперь пишет ИИ-агент, у вас должен быть способ откатиться назад, когда он всё сломает. 💾

<b>GitHub</b> решает простую проблему: когда агент за один ответ меняет десяток файлов и что-то ломает, нужна точка отката. Коммит работает как сохранение в игре с подписью, а откат просто загружает любое из старых сохранений.

Три причины держать код в репозитории, даже если вы сами не программист:
• контрольная точка после каждого рабочего состояния защищает от необратимых правок агента
• хостинги вроде Railway, Render или Vercel сами собирают сайт из репозитория при каждом обновлении
• многие облачные агенты вроде Codex или Claude Code требуют доступ к GitHub, чтобы вообще работать с кодом

По-моему, для человека без опыта разработки это самая полезная привычка на первую же неделю работы с агентом, а не что-то, что можно отложить до первой серьёзной поломки.

Заведите приватный репозиторий уже сегодня и попросите агента включить Git и делать коммит после каждой правки. Один раз сломайте что-то специально и откатитесь: это единственный способ убедиться, что резервный путь правда работает.
```

```
Если у вас в компании есть повторяющийся процесс вроде разбора обращений или обработки видео, теперь его можно собрать без разработчика. 🧩

<b>Yandex AI Studio</b> выпустила визуальный конструктор Workflows для сборки цепочек из нескольких ИИ-агентов. Триггером может быть сообщение в Telegram, вебхук из вашей системы или обычный таймер по расписанию, а дальше данные передаются между шагами без единой строчки кода.

Из готовых сценариев в блоге Яндекса:
• один агент ищет информацию, второй оформляет её в статью

Мне нравится, что это рабочий конвейер, а не чат-бот для разговоров: собрал один раз, и дальше он работает сам по расписанию или по сигналу извне.
```
