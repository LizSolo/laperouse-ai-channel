## 3. OpenAI открыла доступ к Decisions API

Первоисточник: https://vc.ru/ai/3211419-openai-otkryla-dostup-k-decisions-api (открыт целиком, F-01: путь 1)
Подтверждение: не требуется.

Факты:
- Decisions API — модель принятия решений от OpenAI на базе GPT-6 Luna. Отвечает не текстом, а коротким результатом: бинарное решение (predicate, 0-1), выбор из вариантов (choice) или оценка по шкале (score, может включать уверенность).
- Работает с изображениями, текстом и JSON; с GPT-Live можно использовать для аудио в голосовых интерфейсах.
- Примеры применения из статьи: сортировка повреждённых товаров, оценка безопасности команд ИИ-агентов перед выполнением.
- 29 сентября 2026 модель впервые представлена ограниченному кругу пользователей, теперь открыта всем разработчикам; есть демо-режим Decisions Playground.
- Цена: $0,10 за 1 млн входных токенов, $0,01 за 1 млн кэшированных входных токенов; выходные токены не тарифицируются. Для сравнения: конкурент Jev (стартап TypeSafe, модель представлена в сентябре 2026) стоит $0,042 за 1 млн входных токенов.
- Время обработки запроса сократилось с 1-3 секунд до 120-180 миллисекунд (сравнение с предыдущим подходом OpenAI, не с Jev).
- Доступность из России и региональные ограничения в статье не упомянуты.

## 6. Предвзятость с убедительным объяснением: как нейросети дискриминируют кандидатов

Первоисточник: https://habr.com/ru/articles/1098436/ (открыт целиком, F-01: путь 1)
Подтверждение: не требуется.

Факты:
- Дата публикации точно не читается из страницы; метка «14 часов назад» на момент проверки 24.10.2026 и дата дайджеста «23 окт 2026» на странице указывают на 23-24.10.2026.
- Исследование FairStress (Ai2, 2026): 300 сценариев в 29 областях, более 13 млн тестовых заданий. Разрыв в отказах от более сильного кандидата в пользу кандидата из «меньшинства»: 9,3 п.п. при явном указании группы, 6,9 п.п. при косвенном (через диалект/имя). На неоднозначных заданиях модель FairStress-Core выбирала кандидата из меньшинства в 61-65% случаев.
- В исследовании FairStress попытка «исправить» модель Qwen2.5-7B-Instruct через внутреннее вмешательство снизила долю выбора более подходящего кандидата с 98% до 47%.
- Исследование BBQ (Parrish и соавторы, 2022): около 58 тысяч примеров по девяти социальным категориям; у модели UnifiedQA около 77% ошибок на неоднозначных заданиях совпадали со стереотипом (доля среди ошибок, не среди всех ответов).
- Исследование про диалект (Nature, 2024, модели GPT-2/RoBERTa/T5/GPT-3.5/GPT-4): в сценарии обвинения обвинительный исход получался в 68,7% случаев для текста на афроамериканском варианте английского и в 62,1% для стандартного английского — разница 6,6 п.п.
- Исследование Tamkin и соавторов (2023, модель Claude 2.0): 70 сценариев, 9450 вопросов; инструкция не учитывать демографию кандидата заметно уменьшала различия в оценках.
- Рекомендация автора для бизнеса: не полагаться на вердикт модели без проверки, прогонять одно и то же резюме с изменёнными именем/демографическими признаками и смотреть, меняется ли оценка; удаление поля с расой или полом из анкеты не гарантирует отсутствие влияния, так как признаки считываются из текста (например из диалекта). Автор также пишет, что переход на китайские или российские модели не решает проблему — перекос обнаружен и у китайской Qwen, российские модели в разобранных работах не оценивались.

## 7. Сначала радиус поражения: семь рамок перед тем как пустить ИИ на свои серверы

Первоисточник: https://habr.com/ru/articles/1098582/ (открыт целиком, F-01: путь 1)
Подтверждение: не требуется.

Факты:
- Автор: Петр Мамруков (nETPO). Точная дата не читается из страницы; метка «12 часов назад» на момент проверки 24.10.2026 и дата дайджеста «23 окт 2026» на странице, в тексте упомянуто «начало октября» — публикация в районе 22-24.10.2026.
- Личные примеры автора: ИИ-агент случайно опустошил общий node_modules; в другой раз затёр исправления безопасности при слиянии веток.
- Семь рамок: 1) минимальные права — отдельный пользователь без root, точечный sudo, доступ к БД только на нужное, без боевых паролей в доступных агенту файлах; 2) никаких новых открытых портов — доступ через Tailscale/WireGuard или схему, где сервер сам подключается наружу; 3) первая неделя — только чтение, без изменений; 4) снимки/резервные копии перед изменениями, вне досягаемости агента, с проверкой восстановления; 5) повторяющиеся задачи — через скрипты (например плейбуки Ansible), которые человек читает и запускает сам; 6) журнал того, что запускалось, на какой машине и с каким результатом; 7) кнопка «стоп» — быстрая отмена задачи и отключение машины, в том числе с телефона.
- Упомянутые инструменты: Local Commander (собственный продукт автора — агент подключается наружу, права задаются для каждой машины, есть журнал, отмена и облачный ретранслятор; автор сам отмечает, что ретранслятор облачный и может не подойти тем, кто запрещает выход данных за пределы своей сети), MCP-сервер через SSH как альтернатива, Tailscale, WireGuard, SSH, Ansible, git worktree, npm ci.
- Claude Code в статье не упоминается — речь об ИИ-агентах в целом, независимо от выбора инструмента.
