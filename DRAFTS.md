Если вы прототипируете игры в Claude Code, учтите: с конца октября инструмент сам откажется воссоздавать чужую существующую игру. 🎮

Правило всплыло в конце октября: пользователи заметили, что Claude Code отказывается копировать конкретные существующие игры, даже если файлы переименовать или поменять детали механики. По данным Game Developer, Anthropic подтвердила, что обновление модели <b>Opus 5.5</b> теперь направляет Claude Code в сторону от воссоздания чужой конкретной игры.

Отключить это поведение через настройки нельзя: запрет работает на уровне сервера, а не локальной конфигурации.

При этом разработчикам всё ещё открыты три дороги:

🎮 делать полностью свою игру, со своими механиками и ассетами
🎮 работать в рамках жанра без привязки к конкретному названию
🎮 использовать собственные эскизы и наработки как основу

Мне кажется, для небольшой студии или фрилансера это повод формулировать техническое задание через жанр и свой дизайн с самого начала. Прямая просьба переделать конкретную существующую игру теперь рискует закончиться отказом раньше, чем вы доберётесь до интересной части работы.

Если вы или ваша команда используете Claude Code для прототипов, проверьте текущие технические задания и перепишите те, что ссылаются на конкретные существующие игры.

Если в компании ИИ-агенту дали доступ к базе данных или логам, стоит заранее решить, кто подтверждает операции записи. 🔐

Разработчик с ником wbb опубликовал на Хабре открытый проект <b>GateRook</b>: локальный шлюз между ИИ-клиентом и базами или логами компании. Код открыт по лицензии Apache 2.0.

Шлюз работает в несколько шагов: запрос от ИИ сначала проходит классификацию на чтение, запись или запрет, затем политику, и только после этого, если нужно, подтверждение человека.

В проекте четыре режима доступа:

🔧 Off, доступа нет вовсе
🔧 Read-only, можно только смотреть
🔧 Approval, запись идёт только после подтверждения
🔧 Bypass, временный режим только для dev и stage, никогда для продакшена

При подтверждении в журнал попадает точный SQL-запрос, у него ограниченное время жизни: не ответили вовремя, запрос просто истекает.

Автор сам честно пишет про границы: шлюз не ловит прямой доступ к терминалу или сети мимо себя и не решает проблему prompt injection.

Мне кажется, здесь ценнее сама идея отдельного слоя правил для доступа, чем конкретная реализация инструмента.

Если у вас в компании ИИ-агент уже достаёт данные из базы или читает логи, проверьте для начала одно: может ли он без подтверждения человека изменить или удалить данные.

Если для вашего бизнеса настроен свой чат-бот на Claude API, спросите разработчика про функцию, которая снижает задержку ответа. 💬

С 2 ноября в Claude API доступна бета-функция <b>Message threads</b>: сервер Anthropic сам хранит историю диалога, и каждый следующий запрос отправляет только новые сообщения вместо всей переписки с начала.

Для длинных диалогов и агентных цепочек, где история растёт с каждым шагом, это означает меньше данных в каждом запросе и более быстрый первый ответ модели.

У функции есть ограничение по времени: диалог живёт 5 минут после последнего запроса и удаляется не позднее чем через час после последнего использования.

В описании релиза ничего не сказано про изменение цены, речь только про экономию по времени и объёму данных.

Мне кажется, это тот редкий технический релиз, который лучше переслать разработчику целиком, без пересказа своими словами.

Если у вашего бизнеса есть свой бот или агент на Claude API, спросите у подрядчика, подключена ли уже эта функция и что она меняет по скорости ответов.

<b>Codex</b> в объединение не попадёт и останется отдельным разделом приложения.
