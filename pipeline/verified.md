# Проверка фактов за 2026-09-13

## Пост 1. Cursor заблокирован в России после сделки со SpaceX

Первоисточник: https://www.cnews.ru/news/top/2026-09-11_odin_iz_krupnejshih_ii-instrumentov
(открыт целиком через WebFetch, F-01 — путь «первоисточник открыт»)
Подтверждение: https://habr.com/ru/articles/1078814/ (открыт целиком через WebFetch, факты совпадают)

Факты:
- Инструмент: Cursor, ИИ-редактор кода на основе автодополнения и агентов, разработчик — Anysphere
- 4 сентября 2026 Cursor перестал работать для пользователей из России: автодополнение и агентные функции отключены по геолокации
- Причина: SpaceX купила Anysphere в середине августа 2026 за 60 млрд долларов; 3 сентября 2026 в пользовательское соглашение Cursor добавлен пункт 17.5 об экспортном контроле США, запрещающий предоставление сервиса пользователям из стран под эмбарго
- OpenAI ранее (конец августа 2026) уведомила SpaceX о прекращении предоставления моделей ChatGPT для Cursor к 12 ноября 2026 из опасений нарушения условий использования
- Официального заявления Anysphere не было, факт устанавливается по изменению пользовательского соглашения
- Обход через VPN нарушает условия использования и рискует блокировкой аккаунта
- Ранее так же поступали OpenAI (2024), Google Gemini (2025), Anthropic Claude (с весны 2026)
- Альтернативы для разработчиков на 1С, доступные из России без VPN: Aether Lab (браузерный IDE с агентом, 1990 руб/мес), AI Code Maestro (плагин для EDT, 2999 руб/мес), «1С:Напарник» (официальный ассистент 1С, бесплатно до октября 2026), MCP:RSV Server (интеграция с IDE, 1500 руб/мес), 1C Copilot (оплата по факту использования, 103,50 руб за million входных токенов)
- Для разработчиков не на 1С — переход на Claude Code, Codex, модели с открытым кодом или локальные модели

## Пост 2. GitHub простыми словами для тех, кто работает с ИИ-агентами

Первоисточник: https://vc.ru/ai/3134330-chto-takoe-github-i-ego-znachenie-dlya-lyudey
(открыт целиком через WebFetch, F-01 — путь «первоисточник открыт»)
Подтверждение: не требуется, первоисточник открыт целиком

Факты:
- Тема статьи: зачем GitHub нужен людям, которые не пишут код сами, а поручают разработку ИИ-агенту
- Ключевая идея: коммит — это сохранение с подписью, откат — загрузка любого из предыдущих сохранений (аналогия с сохранениями в игре)
- Три причины пользоваться GitHub: 1) версионирование — контрольные точки после каждого рабочего состояния, защита от необратимых правок агента; 2) облачный деплой — хостинги (Railway, Render, Vercel) собирают проект из репозитория при каждом обновлении; 3) облачные агенты (Codex, Claude Code) часто требуют доступ к репозиторию на GitHub для работы
- Конкретные шаги для первой недели: создать приватный репозиторий, попросить агента включить Git и писать коммит после каждой правки, специально сломать что-то в проекте и откатиться на рабочую версию, опубликовать простой сайт через GitHub Pages, разобрать чужой открытый проект с помощью агента

## Пост 5. Claude спроектировала печатную плату по одному промпту

Первоисточник: https://habr.com/ru/news/1081606/ (открыт целиком через WebFetch, F-01 — путь «первоисточник открыт»)
Подтверждение: не требуется, первоисточник открыт целиком; изначальный автор — пользователь Reddit a6m-zero (упомянут в статье, его блог a6mzero.com закрыт для автозапросов egress-прокси)

Факты:
- Автор эксперимента — инженер-любитель, публикация в блоге и на Reddit (r/ClaudeAI), пересказана на Хабре 13.09.2026
- Задача: спроектировать печатную плату для устройства с e-ink экраном GDEY0154D67-FL04, микроконтроллером Raspberry Pi Pico 2 (RP2350), четырьмя кнопками, шиной I2C и выведенными GPIO-контактами
- Промпт был сформулирован одним запросом с перечислением компонентов и требуемого поведения (управление экраном, кнопки для команд)
- Модель: Claude (Fable 5) в автономном режиме; после нескольких часов работы модель сама нашла и исправила ошибки в выборе компонентов (неподходящие SPI-флеш и транзистор), потребовалось несколько циклов итераций
- Затраты: 130 евро на производство 5 плат, 450 долларов на кредиты для работы моделей Claude

## Пост 6. Workflows в Yandex AI Studio — конструктор мультиагентных пайплайнов

Первоисточник: https://yandex.cloud/ru/blog/yandex-ai-studio-workflows-multiagent-pipelines
(открыт целиком через WebFetch, F-01 — путь «первоисточник открыт»)
Подтверждение: не требуется, первоисточник открыт целиком

Факты:
- Дата публикации: 11 сентября 2026
- Workflows — low-code конструктор для автоматизации бизнес-процессов через агентские пайплайны, ориентирован на end-to-end автоматизацию, а не на чат-ботные сценарии
- Триггеры запуска пайплайна: сообщения в Telegram, вебхуки для внешних систем, таймеры по расписанию
- Базовый элемент — «агентский кубик» с настройкой модели, системного промпта, инструментов и формата ответа (текст, JSON, жёсткая схема); передача данных между шагами без кода через «саджесты»
- Управляющие конструкции: Switch (маршрутизация по условиям), параллельное выполнение независимых агентов, режим отладки отдельных элементов
- Примеры сценариев из статьи: поиск информации одним агентом и оформление статьи другим; обработка видео (форма → извлечение аудио → распознавание речи → саммаризация → письмо на почту); анализ тональности текста с маршрутизацией по сценариям
- Расширение через HTTP-запросы, gRPC, Yandex Cloud Functions, Yandex Serverless Containers; готовый пайплайн можно обернуть в MCP-инструмент через MCP Hub для вызова другими агентами
- Цены и тарифный порог доступности в статье не указаны — не пишем цифры в пост
