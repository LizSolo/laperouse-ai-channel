## Пост 3

```
Если в компании уже пользуются Claude или Cursor, свою базу данных для них не обязательно копировать в чат вручную. 🔌

Есть открытый протокол <b>MCP</b> (Model Context Protocol): он подключает ИИ-модель напрямую к вашим данным, без отдельного бэкенда под каждую интеграцию.

На vc.ru разобрали, как поднять такой сервер за один вечер:

⚙️ установить пакетный менеджер uv
🐍 написать сервер на фреймворке FastMCP на Python
🔒 подключить к нему базу данных в режиме только для чтения
🖥️ прописать сервер в настройках Cursor или Claude Desktop

Поддерживают такое подключение сразу несколько приложений: Cursor, Claude Desktop, Windsurf и Zed.

Мне кажется, здесь дело не столько в самом протоколе, сколько в том, что для такой интеграции не нужен отдельный бэкенд-проект: разовая настройка, и дальше модель видит ваши данные напрямую.

Если в команде есть кто-то, кто пишет код, попросите его собрать такой сервер под одну конкретную задачу, например подключить Claude к логам поддержки или к базе заказов.
```

## Пост 4

```
Если в компании администратор вручную ведёт список доверенных доменов в Google Workspace, для этого теперь есть более быстрый способ. 📋

20 августа Google выпустил <b>Allowlisted Domains API</b>: домены можно добавлять, удалять и выгружать списком через API вместо ручного редактирования в консоли.

Доступно это всем клиентам Google Workspace, но нужны права администратора на управление доменами: обычным сотрудникам эта настройка не видна. Раньше при каждом новом партнёре или подрядчике приходилось заходить в консоль и добавлять домен руками, а теперь то же самое можно завернуть в скрипт и запускать по расписанию.

Мне кажется, для маленькой компании, где и так один-два человека отвечают за IT, такая мелочь освобождает вам время на что-то более важное, чем клики в консоли администратора.

Если ваш администратор Workspace регулярно обновляет список доверенных доменов вручную, покажите ему эту функцию: настройку через API можно один раз завернуть в скрипт и больше не возвращаться к консоли.
```

## Пост 5

```
Если в компании уже строите или заказываете ИИ-агента под свой процесс, для его инструкций не обязательно отдельное хранилище. 🗂️

В начале августа в <b>Claude Managed Agents</b> добавили возможность подгружать skills, то есть готовые инструкции и рабочие процессы, прямо из GitHub-репозитория, который уже подключён к сессии агента.

Всё, что лежит в папке .claude/skills в корне репозитория, агент подхватывает автоматически при старте сессии, без ручной загрузки файлов в каждого агента отдельно.

Формат тот же, что и у skills, загруженных вручную, поэтому переносить существующие инструкции не придётся: достаточно положить их в нужную папку репозитория.

Мне кажется, ценность здесь не столько в самой функции, сколько в привычном рабочем процессе: обновили инструкцию обычным коммитом, и агент в следующей сессии уже работает по-новому.

Если у вашей команды уже есть репозиторий с шаблонами и регламентами, попробуйте вынести инструкции для агента туда, а не держать их в отдельном месте, до которого никто не доходит.
```
