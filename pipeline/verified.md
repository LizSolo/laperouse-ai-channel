## Пост 4. GateRook: доступ ИИ-агента к базам и логам с контролем изменений

- Первоисточник: https://habr.com/ru/articles/1102946/ (Хабр, автор wbb)
- Подтверждение: открыт целиком через WebFetch, второй источник не требуется (F-01, путь 1)
- Факты:
  - GateRook — локальное приложение и MCP-шлюз с открытым кодом (лицензия Apache 2.0) между ИИ-клиентом и базами/логами компании
  - Запрос проходит классификацию (чтение/запись/запрещено), политики и, если нужно, подтверждение человеком, и только потом коннектор его выполняет
  - Режимы: Off, Read-only, Approval и Bypass; Bypass работает только для dev и stage, не распространяется на production
  - При подтверждении сохраняется точный SQL-запрос; ядро повторно проверяет условия перед запуском; запрос с ограниченным временем жизни истекает без решения
  - Секреты хранятся в локальном зашифрованном хранилище, результаты маскируются до записи в журнал, журнал Activity фиксирует все вызовы
  - Автор признаёт: шлюз не контролирует прямой доступ к терминалу или сети, не решает проблему prompt injection и не защищает скомпрометированную рабочую станцию

## Пост 5. Эксперимент: DeepSeek патчит ошибки 1С вместо ожидания обновления вендора

- Первоисточник: https://habr.com/ru/articles/1102948/ (Хабр, автор sokolov_e_s)
- Подтверждение: открыт целиком через WebFetch, второй источник не требуется (F-01, путь 1)
- Факты:
  - Тест слепой: агенту давали только описание симптома ошибки, официальные патчи 1С (`EF_...`) использовались как эталон для сравнения
  - Инструмент — десктопная консоль кода с ИИ, модель deepseek-v4-flash; тестовая база — 1С:Управление нашей фирмой (УНФ) 3.0.12.261, часть кейсов на релизе 3.0.14
  - Исправления оформлялись как расширения 1С (не меняют типовую конфигурацию, можно отключить)
  - Кейс 1 (деление на ноль при печати УПД): 5 из 5 успешных исправлений, близко к патчу вендора
  - Кейс 2 (не создаётся операция по платёжным картам): 5 из 5, почти полное совпадение с патчем
  - Кейс 3 (ошибка кнопки «Оплата через СБП» без банковского счёта): 4 из 5; вендор в итоге точнее поправил опечатку в тернарном операторе
  - Кейс 4 (доработки из УНФ 3.0.14 — «Установка цен» из заказа и печать «Переоценки товаров»): 3+ из 5; агент не знал штатных механизмов БСП и создавал побочные эффекты (черновик в базе до открытия формы)
  - Автор: LLM не заменяет обновления вендора, агенту не хватает знаний архитектуры БСП, фикс не всегда точнее вендорского

## Пост 7. Claude API: Message threads сокращают историю запроса в длинных диалогах агентов

- Первоисточник: https://platform.claude.com/docs/en/release-notes/overview (Claude Platform, запись от 2 ноября 2026)
- Подтверждение: открыт целиком через WebFetch, второй источник не требуется (F-01, путь 1)
- Факты:
  - Message threads (бета) хранит историю диалога на сервере Anthropic; каждый следующий запрос передаёт только новые сообщения вместо всей истории
  - Включается через beta-заголовок `message-threads-2026-08-12`
  - Тред живёт 5 минут после последнего запроса и удаляется не позднее чем через 1 час после последнего использования
  - Эффект: меньше данных в каждом запросе и ниже time to first token в длинных диалогах и агентных циклах
  - Доступно в Claude API, Claude Platform on AWS, Claude Models on Google Cloud (Anthropic managed) и Claude in Microsoft Foundry
  - В релизе не сказано об изменении цены — указана только экономия по времени и объёму запросов; нужна интеграция на стороне разработчика (минимум — добавить beta-заголовок)
